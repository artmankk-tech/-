# QUEST｜習慣と仕事のRPG

小さな行動で架空の社員を育てる、人生ゲーム風のiPhone向けWebアプリです。仕事とプライベートは別々の社員・記録・持ち物で遊べます。ビルド不要で、外部サービス・利用料金・アカウント登録はありません。記録は端末内に保存します。

公開URL：**https://artmankk-tech.github.io/-/**

リポジトリ：**https://github.com/artmankk-tech/-**

操作メニューを先に表示するv7です。ミッション操作と「ミッション・タイマー・着せ替え」のメニューを画像より上に配置しました。キャラクターは「寡黙な実力派」に変更しました。過去のミッション・XPを引き継ぎ、成長とアプリ内コインを追加しました。過去の育成データの保持に加え、公開URLで画像表示・家具交換・JSON復元・画像を含むオフライン動作を確認済みです。iPhone実機での最終確認は未完了です。詳しくは [TEST_RESULTS.md](TEST_RESULTS.md) を参照してください。

## iPhoneで始める

1. 上の公開URLをSafariで開きます。
2. 共有ボタン →「ホーム画面に追加」→「追加」を選びます。iOSにより表示位置は異なります。
3. ホーム画面のQUESTを起動します。Safariですでに記録した場合は、Safari側でJSONバックアップし、ホーム画面側で復元してください。保存領域が異なる場合があります。
4. 「仕事」または「プライベート」を選び、画像より上の「今日の小さな一歩」の「達成」を押します。一覧から選ぶ場合は「ミッション」、集中する場合は「タイマー」、衣装等を見る場合は「着せ替え」で各画面へ移動できます。一覧の□を再タップすると達成を取り消せます。
5. ☆で今日の重要ミッションを3件まで選べます。取りかかれないときは2分タイマーや再開ボーナスを使います。未達成への罰則はありません。
6. 「記録はこの端末に保存されています」と表示されていることを確認します。初回はオンラインで起動し、データ管理の「オフライン用ファイルを準備しました」を確認します。

アプリ内の「？ 使い方・iPhone設定」からも説明を開けます。

## 社員を育てる人生ゲーム

画面上部の社員は、あなたの行動で成長する架空のキャラクターです。実在の社員管理や人事評価には使いません。

| 成長XP | 社員のステージ | 人生イベント |
| --- | --- | --- |
| 0 | 新入社員 | はじめての出社 |
| 100 | 一人前 | 自分の名刺をもらった |
| 300 | 頼れる先輩 | 後輩からの「ありがとう」 |
| 600 | リーダー | 小さなチームを任された |
| 1000 | マネージャー | 眺めのよい席へお引っ越し |
| 1500 | 社長 | 自分らしい会社ができた |

- ミッション、タイマー、再開ボーナスのXPで成長します。成長XPは記録した累積XPの最高値です。休んだり、当日の達成を取り消したりしても降格しません。通常の累積XP表示は、従来どおり当日の取り消しを反映します。
- 黒髪・クールな顔立ちの成人男性アニメキャラクターを採用しています。新人の白シャツとベスト姿から、昇格に合わせてスーツ・メガネ・ピンなどが変わります。購入済みの衣装を選んでいる間は、その衣装の姿を優先します。画面上部の「今日の小さな一歩」から、その日の重要ミッションを優先して1タップで達成できます。
- ミッションは獲得XPと同じ数のコイン（C）を各モード・各ミッション1日1回受け取れます。チェック取り消しではコインを減らしません。同じ日の再チェックやXP編集では二重付与しません。
- タイマー完了は10 Cを各モード1日1回、再開は5 Cを各モード1日3回まで。XPの付与上限と同じです。
- コインで衣装・部屋・家具を交換するとすぐに反映されます。購入済みの服・部屋は無料で切り替えられ、家具は「飾る／しまう」を選べます。XPや成長は交換に使いません。現実のお金・課金・現実の行動を条件にした報酬はありません。
- 最初の家具は20 C、衣装は30 Cから。衣装4種類、部屋3種類、家具3種類があります（無料の初期アイテムを含む）。
- 旧データを初めて開くと、それまでの累積XPを成長XPと初期コインに変換します。再起動のたびに付与することはありません。日別記録と過去の獲得XPは保持します。

## バックアップと復元

- 毎週・更新前・復元前に「JSONバックアップ」を押し、iPhoneの「ファイル」など、後から見つけられる場所に保存してください。両モードのミッション・XP・社員の成長・コイン・持ち物・使用中の衣装や部屋を1つのJSONに含めます。
- 「バックアップ復元」でJSONを選ぶと、仕事・プライベートの両方の記録と育成・持ち物を置き換えます。確認画面でキャンセルできます。不正な形式は拒否し、保存が成功してから画面の記録を切り替えます。
- 復元直前の端末内データも別キーに残します。ただし、ブラウザの保存領域が消えると一緒に消えるため、ファイルとしてのバックアップが必要です。
- 保存エラーは画面上部に表示し続けます。その間の操作結果は端末に残っていない可能性があります。読み込み直す前にJSONバックアップを保存してください。
- 既存データを読み込めない場合は自動上書きを停止します。「元の保存データを書き出す」で元の文字列も保全できます。この `quest-recovery-*.json` は調査・救出用で、そのまま通常の復元に使えるファイルではありません。
- 同じ記録を複数のタブで開き、別の画面の更新を検出した場合も上書きを止めます。必要なバックアップを保存し、使う画面を1つにして読み込み直してください。同時操作の完全な同期機能はありません。

データは自動同期されません。プライベートブラウズは避け、バックアップ前にサイトデータを削除しないでください。

## このリポジトリのGitHub Pages設定

既存の公開URLを使い続ける場合、リポジトリ名を変更する必要はありません。

1. GitHubの `artmankk-tech/-` を開き、Settings → Pagesを開きます。
2. Build and deploymentで **Deploy from a branch**、ブランチ **main**、フォルダー **/(root)** を選び、必要ならSaveします。公開済みで設定が正しい場合は変更不要です。
3. main直下に `index.html`、`game.js`、`app.js`、`assets/employee-atlas.png`、`style.css`、`sw.js`、`manifest.webmanifest`、`icon-192.png`、`icon-512.png`、`.nojekyll` を置きます。
4. GitHubのActionsでPagesの処理が完了するのを待ち、Settings → Pagesに表示されたURLを開きます。

別のリポジトリへ配置する場合もファイル構成は同じです。アプリのURLは通常 `https://ユーザー名.github.io/リポジトリ名/` になります。すべてのアセットは相対パスなのでサブパスでも動作します。ただしURLを変更すると元の保存領域を引き継げない場合があるため、移動前にJSONバックアップを保存してください。

**アプリのソースは公開されます。個人情報・社員情報・顧客情報・業務機密・バックアップJSON・回復用JSONをリポジトリにアップロードしないでください。** `.gitignore` はバックアップと回復用JSONを除外しますが、GitHub画面からの手動アップロードは自分で確認してください。

## 更新方法

1. 現在のアプリで両モードのXPを確認し、JSONバックアップを保存します。
2. 修正がPull requestになっている場合はFiles changedで内容を確認し、レビュー完了後にmainへマージします。ZIPから手動更新する場合は展開し、フォルダーごとではなく、中の公開ファイルを同じ場所へアップロードしてCommit changesします。
3. HTML・JS・CSS・アイコンなどを変更する際は、`sw.js` の `const CACHE = PREFIX + 'v7'` の **v7をv8など未使用の値へ変更**し、変更したファイルを同じコミットに含めます。今回の操作メニュー改善版はv7です。画像を更新する場合もキャッシュ名を変更してください。
4. Pagesの更新完了後、オンラインでQUESTを開いて新しいファイルの準備を待ちます。v4以降は更新版が準備できるとデータ管理欄に案内を表示します。
5. QUESTを開いているSafariのタブとホーム画面アプリをすべて閉じ、開き直します。旧画面が開いている間は更新版が待機します。単に別のアプリへ切り替えるだけでは更新されない場合があります。
6. 両モードのXPと記録を確認します。その後、機内モードで起動・操作・再起動も試します。更新のためにサイトデータを削除する必要はありません。

キャッシュは公開URLのスコープごとに管理します。v3以前の共通名キャッシュは、別のアプリが使う可能性があるため自動削除しません。記録の保存領域を更新時に削除する処理はありません。

## アプリの仕様

- 仕事／プライベートそれぞれに、ミッション・XP・レベル・報酬・日別記録・タイマーがあります。
- 累積XPは日付変更、ミッション編集・削除でも維持します。当日のチェック取り消しは、その達成時点のXPを取り消します。日付は端末のローカル日付です。
- 保存キー `quest-rpg-v1` を継続使用します。新しいバックアップは育成を含む `version:3`、旧 `version:1/2` の復元も可能です。旧バックアップの復元では持ち物を初期化し、そのバックアップのXPから育成を始めます。新しいJSONは旧アプリでは復元できません。育成導入前の原本を `quest-rpg-v1-pre-life-game`、従来の移行前原本を `quest-rpg-v1-pre-upgrade`、復元前原本を `quest-rpg-v1-before-restore` に保持します。旧版ですでに失われたXPは復元できません。
- タイマーは2分・15分。両モードで独立して進み、開始モードへ完了ボーナス10 XPを各モード1日1回付与します。再開ボーナスは5 XPを各モード1日3回までです。
- 画面ロックから戻ると実経過時間を反映します。通知・音はありません。再読み込み・アプリの完全終了でタイマーはリセットされます。日付変更時は一時停止中を含む両モードのタイマーをリセットし、日をまたぐ完了ボーナスは付与しません。
- 報酬はアプリ内ショップの衣装・部屋・家具です。コインだけを消費し、XPは消費しません。以前の現実の休憩等の報酬はショップから置き換えました。過去の受取記録は日別データに保持します。
- 日別の直近7日XPと週間合計を表示します。記録のない日に減点はありません。
- ブラウザやOSに保存領域・キャッシュを削除されることがあります。定期バックアップと、必要時のオンライン再起動を行ってください。

## 開発者向けの確認手順

利用者に開発ツールは不要です。静的ファイルを編集すれば更新できます。

ローカル起動：このフォルダーで `python3 -m http.server 8000 --bind 127.0.0.1` を実行し、`http://127.0.0.1:8000` を開きます。HTMLファイルを直接開く方法ではPWA・オフライン動作を確認できません。

テストにはNode.js、Playwright、Chromiumと、旧版コミットを含むGitチェックアウトを使います。Playwrightがない環境では `npm install --no-save playwright` と `npx playwright install chromium` で準備します。

```sh
node --check game.js
node --check app.js
node --check sw.js
node tests/reliability.cjs
node tests/game.cjs
node tests/character.cjs
```

`reliability.cjs` は一時HTTPサーバーを自動起動します。`/-/` サブパス、タッチ操作、実際のJSONダウンロード内容、保存失敗、破損データ保全、日付変更、v3→v5の更新を検証します。`game.cjs` はv4→v5の実更新、過去XPの移行、昇格、コイン二重取得防止、購入失敗時の取り消し、育成付きJSON復元、オフライン装備変更を検証します。更新テストはGitから既存コミット `8c3fd31` と `fc77fb7` を読み取るため、ZIPを展開しただけのフォルダーでは実行できません。

既存テストは上の8000番サーバーを起動した状態で `node tests/browser.cjs` を実行します。システムの `/usr/bin/chromium` があれば使用し、なければPlaywrightのChromiumを使います。別の場所にある場合は `CHROMIUM_PATH` で指定できます。

公開URLの確認には `node tests/published.cjs` を使います。新しいブラウザ保存領域だけで操作し、サーバーや利用者端末の記録には書き込みません。配信ファイルがローカルのテスト対象と一致すること、保存・復元、オフライン起動を検証します。実行前に、検証する修正版が公開済みである必要があります。別の配置先では末尾が `/` のURLを `QUEST_BASE_URL` で指定します。`HTTPS_PROXY` / `HTTP_PROXY` がある環境では、そのプロキシを使います。

## キャラクター画像の構成

`assets/employee-atlas.png` は透過PNGの3列×3行の素材です。上段左から新人・一人前・先輩、中段がリーダー・マネージャー・社長、下段がミント・コーラル・星空の衣装です。キャラクターは架空の成人男性です。生成したイラストをローカルの静的ファイルとして同梱し、表示時に外部画像サービスへアクセスしません。

画像だけを変更する更新でも `assets` フォルダーをアップロードし、`sw.js` のキャッシュ名を変えてください。フォルダーを省くと画像表示と初回のオフライン準備が失敗します。JPEG等へ名前だけ変更する方法は使わず、透過PNGのまま配置します。

`node tests/character.cjs` は実際の公開済みv5からv6への更新、元の保存データとの完全一致、3衣装、画像のデコード、オフライン画像読み込みを確認します。旧版コミットを含むGitチェックアウトが必要です。保存キー・育成データの形式・JSON version:3はv5から変更していません。

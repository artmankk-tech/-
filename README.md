# QUEST｜習慣と仕事のRPG

仕事とプライベートを分け、小さな行動にXPを付けるiPhone向けWebアプリです。ビルド不要で、外部サービス・利用料金・アカウント登録はありません。記録は端末内に保存します。

公開URL：**https://artmankk-tech.github.io/-/**

リポジトリ：**https://github.com/artmankk-tech/-**

2026-11-08にv4修正版をmainへマージし、GitHub Pagesで公開しました。公開URLで両モードの記録保持、JSONバックアップ・復元、オフライン操作と再起動を確認済みです。iPhone実機での最終確認は未完了です。詳しくは [TEST_RESULTS.md](TEST_RESULTS.md) を参照してください。

## iPhoneで始める

1. 上の公開URLをSafariで開きます。
2. 共有ボタン →「ホーム画面に追加」→「追加」を選びます。iOSにより表示位置は異なります。
3. ホーム画面のQUESTを起動します。Safariですでに記録した場合は、Safari側でJSONバックアップし、ホーム画面側で復元してください。保存領域が異なる場合があります。
4. 「仕事」または「プライベート」を選び、ミッション左の□をタップすると達成になります。再タップで取り消せます。
5. ☆で今日の重要ミッションを3件まで選べます。取りかかれないときは2分タイマーや再開ボーナスを使います。未達成への罰則はありません。
6. 「記録はこの端末に保存されています」と表示されていることを確認します。初回はオンラインで起動し、データ管理の「オフライン用ファイルを準備しました」を確認します。

アプリ内の「？ 使い方・iPhone設定」からも説明を開けます。

## バックアップと復元

- 毎週・更新前・復元前に「JSONバックアップ」を押し、iPhoneの「ファイル」など、後から見つけられる場所に保存してください。両モードを1つのJSONに含めます。
- 「バックアップ復元」でJSONを選ぶと、仕事・プライベートの両方を置き換えます。確認画面でキャンセルできます。不正な形式は拒否し、保存が成功してから画面の記録を切り替えます。
- 復元直前の端末内データも別キーに残します。ただし、ブラウザの保存領域が消えると一緒に消えるため、ファイルとしてのバックアップが必要です。
- 保存エラーは画面上部に表示し続けます。その間の操作結果は端末に残っていない可能性があります。読み込み直す前にJSONバックアップを保存してください。
- 既存データを読み込めない場合は自動上書きを停止します。「元の保存データを書き出す」で元の文字列も保全できます。この `quest-recovery-*.json` は調査・救出用で、そのまま通常の復元に使えるファイルではありません。
- 同じ記録を複数のタブで開き、別の画面の更新を検出した場合も上書きを止めます。必要なバックアップを保存し、使う画面を1つにして読み込み直してください。同時操作の完全な同期機能はありません。

データは自動同期されません。プライベートブラウズは避け、バックアップ前にサイトデータを削除しないでください。

## このリポジトリのGitHub Pages設定

既存の公開URLを使い続ける場合、リポジトリ名を変更する必要はありません。

1. GitHubの `artmankk-tech/-` を開き、Settings → Pagesを開きます。
2. Build and deploymentで **Deploy from a branch**、ブランチ **main**、フォルダー **/(root)** を選び、必要ならSaveします。公開済みで設定が正しい場合は変更不要です。
3. main直下に `index.html`、`app.js`、`style.css`、`sw.js`、`manifest.webmanifest`、`icon-192.png`、`icon-512.png`、`.nojekyll` を置きます。
4. GitHubのActionsでPagesの処理が完了するのを待ち、Settings → Pagesに表示されたURLを開きます。

別のリポジトリへ配置する場合もファイル構成は同じです。アプリのURLは通常 `https://ユーザー名.github.io/リポジトリ名/` になります。すべてのアセットは相対パスなのでサブパスでも動作します。ただしURLを変更すると元の保存領域を引き継げない場合があるため、移動前にJSONバックアップを保存してください。

**アプリのソースは公開されます。個人情報・社員情報・顧客情報・業務機密・バックアップJSON・回復用JSONをリポジトリにアップロードしないでください。** `.gitignore` はバックアップと回復用JSONを除外しますが、GitHub画面からの手動アップロードは自分で確認してください。

## 更新方法

1. 現在のアプリで両モードのXPを確認し、JSONバックアップを保存します。
2. 修正がPull requestになっている場合はFiles changedで内容を確認し、レビュー完了後にmainへマージします。ZIPから手動更新する場合は展開し、フォルダーごとではなく、中の公開ファイルを同じ場所へアップロードしてCommit changesします。
3. HTML・JS・CSS・アイコンなどを変更する際は、`sw.js` の `const CACHE = PREFIX + 'v4'` の **v4をv5など未使用の値へ変更**し、変更したファイルを同じコミットに含めます。今回の修正版はv4です。
4. Pagesの更新完了後、オンラインでQUESTを開いて新しいファイルの準備を待ちます。v4以降は更新版が準備できるとデータ管理欄に案内を表示します。
5. QUESTを開いているSafariのタブとホーム画面アプリをすべて閉じ、開き直します。旧画面が開いている間は更新版が待機します。単に別のアプリへ切り替えるだけでは更新されない場合があります。
6. 両モードのXPと記録を確認します。その後、機内モードで起動・操作・再起動も試します。更新のためにサイトデータを削除する必要はありません。

キャッシュは公開URLのスコープごとに管理します。v3以前の共通名キャッシュは、別のアプリが使う可能性があるため自動削除しません。記録の保存領域を更新時に削除する処理はありません。

## アプリの仕様

- 仕事／プライベートそれぞれに、ミッション・XP・レベル・報酬・日別記録・タイマーがあります。
- 累積XPは日付変更、ミッション編集・削除でも維持します。当日のチェック取り消しは、その達成時点のXPを取り消します。日付は端末のローカル日付です。
- 保存キー `quest-rpg-v1` とバックアップ `version:2` を継続使用します。旧データの移行前原本を `quest-rpg-v1-pre-upgrade`、復元前原本を `quest-rpg-v1-before-restore` に保持します。旧版ですでに失われたXPは復元できません。
- タイマーは2分・15分。両モードで独立して進み、開始モードへ完了ボーナス10 XPを各モード1日1回付与します。再開ボーナスは5 XPを各モード1日3回までです。
- 画面ロックから戻ると実経過時間を反映します。通知・音はありません。再読み込み・アプリの完全終了でタイマーはリセットされます。日付変更時は一時停止中を含む両モードのタイマーをリセットし、日をまたぐ完了ボーナスは付与しません。
- 報酬は累積XPで解放し、XPは消費しません。各モードで各報酬を1日1回受け取れます。報酬は原則として無料で楽しめる内容です。
- 日別の直近7日XPと週間合計を表示します。記録のない日に減点はありません。
- ブラウザやOSに保存領域・キャッシュを削除されることがあります。定期バックアップと、必要時のオンライン再起動を行ってください。

## 開発者向けの確認手順

利用者に開発ツールは不要です。静的ファイルを編集すれば更新できます。

ローカル起動：このフォルダーで `python3 -m http.server 8000 --bind 127.0.0.1` を実行し、`http://127.0.0.1:8000` を開きます。HTMLファイルを直接開く方法ではPWA・オフライン動作を確認できません。

テストにはNode.js、Playwright、Chromiumと、旧版コミットを含むGitチェックアウトを使います。Playwrightがない環境では `npm install --no-save playwright` と `npx playwright install chromium` で準備します。

```sh
node --check app.js
node --check sw.js
node tests/reliability.cjs
```

`reliability.cjs` は一時HTTPサーバーを自動起動します。`/-/` サブパス、タッチ操作、実際のJSONダウンロード内容、保存失敗、破損データ保全、日付変更、v3→v4の更新を検証します。更新テストはGitから既存コミット `8c3fd31` を読み取るため、ZIPを展開しただけのフォルダーでは実行できません。

既存テストは上の8000番サーバーを起動した状態で `node tests/browser.cjs` を実行します。システムの `/usr/bin/chromium` があれば使用し、なければPlaywrightのChromiumを使います。別の場所にある場合は `CHROMIUM_PATH` で指定できます。

公開URLの確認には `node tests/published.cjs` を使います。新しいブラウザ保存領域だけで操作し、サーバーや利用者端末の記録には書き込みません。配信ファイルがローカルのテスト対象と一致すること、保存・復元、オフライン起動を検証します。実行前に、検証する修正版が公開済みである必要があります。別の配置先では末尾が `/` のURLを `QUEST_BASE_URL` で指定します。`HTTPS_PROXY` / `HTTP_PROXY` がある環境では、そのプロキシを使います。
